# Angular × Nx 每日技術筆記 — 2026-09-11

> 今日主軸：Angular 最新版本 × Angular 21 LTS × Signal Forms × Nx Monorepo

## ⭐ 今日最值得看的 Angular 技術

目前 Angular 22 是 Active 版本；Angular 21 已進入 LTS，支援到 2027 年 6 月。對現有 Angular 21 專案而言，今天最值得投入的不是為了升版而升版，而是先掌握 Signal Forms、Signals 與目前 Angular 的 model-driven 開發方式，再評估升級節奏。citeturn0search14

Angular 官方目前把 Signal Forms 定位成建立在 Signals 上的表單狀態管理方案。它透過一個 writable signal 作為表單模型，再由 `form()` 建立對應的 FieldTree，HTML 使用 `[formField]` 綁定，因此 UI 與資料模型可以自動同步。Signal Forms 需要 Angular v21 或更高版本。citeturn0search0turn0search1

### 為什麼值得現在學？

如果你的 Angular 專案正在逐步採用 Signals，Signal Forms 的思路會比單純把 Reactive Forms API 換掉更重要：

```text
Form UI
  ↓
FieldTree
  ↓
Signal Form Model
  ↓
API DTO / Domain Model
```

核心觀念是：**表單資料模型成為單一來源，而表單狀態由 FieldTree 衍生出來。**citeturn0search2

> 注意：Angular 官方目前也提醒，既有 Reactive Forms 專案不需要為了 Signal Forms 強制重寫；Signal Forms 特別適合新的、以 Signals 為核心的應用。citeturn0search1

## 🔍 核心概念 / API

### 1. `signal()`：表單資料模型

```ts
interface LoginData {
  email: string;
  password: string;
  rememberMe: boolean;
}

loginModel = signal<LoginData>({
  email: '',
  password: '',
  rememberMe: false,
});
```

這個 signal 就是表單資料的來源。官方教學也是先建立 interface，再使用 `signal()` 保存表單值。citeturn0search5

### 2. `form()`：建立 FieldTree

```ts
loginForm = form(this.loginModel);
```

`form()` 不只是回傳另一個 signal，而是建立一棵 FieldTree：

```text
loginForm
├── email
├── password
└── rememberMe
```

因此可以直接使用：

```ts
loginForm.email
loginForm.password
```

### 3. `[formField]`：連接 HTML

```html
<input
  type="email"
  [formField]="loginForm.email"
/>

<input
  type="password"
  [formField]="loginForm.password"
/>
```

使用者輸入會同步更新 model；model 更新也會反映到 UI。citeturn0search0

# 💻 可以直接實作的範例

下面是一個最小的 Signal Form：

```ts
import { Component, signal } from '@angular/core';
import { FormField, form } from '@angular/forms/signals';

interface LoginData {
  email: string;
  password: string;
}

@Component({
  selector: 'app-login',
  imports: [FormField],
  template: `
    <input
      type="email"
      placeholder="Email"
      [formField]="loginForm.email"
    />

    <input
      type="password"
      placeholder="Password"
      [formField]="loginForm.password"
    />

    <pre>{{ loginModel() | json }}</pre>
  `,
})
export class LoginComponent {
  loginModel = signal<LoginData>({
    email: '',
    password: '',
  });

  loginForm = form(this.loginModel);
}
```

實務上可以先把它放在一個獨立 feature 裡，不要一次改掉整個既有 Reactive Forms 架構。

# 🆕 Signal Forms 教學 — Day 1

## Day 1：建立第一個 Signal Form

今天只學三件事情：

```text
1. signal()  → 保存表單資料
2. form()    → 建立 FieldTree
3. formField → 綁定 HTML
```

### 練習

把下面的資料模型建立起來：

```ts
interface UserData {
  name: string;
  email: string;
  phone: string;
}
```

然後建立：

```ts
userModel = signal<UserData>({
  name: '',
  email: '',
  phone: '',
});

userForm = form(this.userModel);
```

HTML：

```html
<input [formField]="userForm.name" />
<input [formField]="userForm.email" />
<input [formField]="userForm.phone" />
```

### 今天要理解的重點

不要先背 API。

先理解這個關係：

```text
userModel = signal(...)
        ↓
userForm = form(userModel)
        ↓
userForm.name
userForm.email
userForm.phone
        ↓
[formField]
        ↓
HTML
```

Angular 官方也提供完整的 Signal Forms 互動式教學，學習順序包含 model → template → validation → error → submit。citeturn0search3

# 🅱️ Nx Monorepo 實戰

你的團隊是 Nx Monorepo，因此 Signal Forms 不建議直接散落在各個 Angular App 裡。

可以先採用這種結構：

```text
apps/
  eip-web/

libs/
  feature/
    user/

  ui/
    form-field/

  data-access/
    user/
```

例如：

```text
libs/feature/user
        ↓
使用 Signal Forms
        ↓
libs/ui/form-field
        ↓
共用 UI 元件
        ↓
libs/data-access/user
        ↓
API / DTO
```

這樣的切法可以讓 Feature、UI、Data Access 的責任比較清楚。

### Nx Affected

當 Monorepo 中只有某個 feature 被修改時，可以利用 Nx Affected 只執行受影響的專案，而不是每次把整個 Monorepo 全部測試。Nx 官方也建議將 Affected 與 Remote Cache、Distributed Task Execution 搭配使用。citeturn0search15

常用指令：

```bash
nx graph --affected
```

查看哪些專案受到變更影響。citeturn0search15

例如：

```text
修改
libs/data-access/user
        ↓
Nx Project Graph
        ↓
找出依賴 user data-access 的 projects
        ↓
只執行 affected test / build / lint
```

這就是 Nx 在 Angular Monorepo 裡真正有價值的地方：**不是把專案放在同一個 Repository，而是讓工具知道專案之間的依賴關係。**

# 🔄 Angular 21 ↔ 最新 Angular

| 項目 | Angular 21 | Angular 22 |
|---|---|---|
| 支援狀態 | LTS | Active |
| 發布 | 2025-11-19 | 2026-06-03 |
| LTS 結束 | 2027-06 | 2028-06 |
| Signal Forms | 可使用 | 可使用 |
| 適合策略 | 穩定維護 | 新功能優先 |

Angular 官方目前列出的支援版本中，Angular 21 是 LTS、Angular 22 是 Active。citeturn0search14

對企業 Angular 專案，我會建議：

```text
Angular 21
   ↓
先採用適合的 Signals / Signal Forms
   ↓
整理 Nx boundaries
   ↓
改善測試與 affected CI
   ↓
再安排 Angular 22 升級
```

而不是：

```text
Angular 22 出了
↓
所有 App 馬上升級
↓
順便大改 Forms
↓
順便重構 shared components
```

這種一次改太多東西的方式，對企業 Monorepo 的風險通常比較高。
